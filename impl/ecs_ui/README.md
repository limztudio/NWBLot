# Custom UI ECS adapter

`UiLayerSystem` borrows the world, graphics runtime, input dispatcher, clipboard/text-input services and asset manager. It owns `Ui::Context`, `Ui::Builder`, text/paint services and the independent `Ui::GpuRenderer`. `UiPaintContext.ui` exposes the builder alongside low-level paint/text. Components stay in `components.h`; CPU UI code includes no ECS/native headers and GPU work sees only frozen paint. The former ImGui system, draw callbacks, upload/texture helpers and forwarding path have been removed.

Visible `UiPaintComponent` roots are sorted by explicit `order`, then their complete generational EntityID. Removing/hiding a root retires its input/actions even while a GPU snapshot is pending. Callbacks execute on the owning main thread only when a new frame can be built. Their mutable captured state stays alive if the callback removes or replaces its component. A pending generation retries frozen data without rebuilding callbacks or replaying their actions.

The candidate hit layout has the same generation as submitted paint. Final output acceptance identifies the acquired backbuffer used by that generation; only its exact native presentation receipt publishes the layout. A later scene-only frame cannot qualify it. Rejected matching presentation abandons the candidate before rebuilding. This is accepted native queueing, rather than display scan-out completion. Resize/DPI/device boundaries clear stale input geometry.

Native handler dispatch joins outstanding world work before reading roots. System update uses scheduler component dependencies and never joins its own task. Coordinates are logical; the OS dispatcher normalizes DPI. The first held pointer button assigns scene/custom ownership through release, including wheel input. Supported held UI keys keep their owner across focus transfer. Focus broadcasts and key/button releases visit all handlers.

Win32, X11 and Wayland deliver native pointer leave and capture-loss boundaries. Leave clears hover while retaining capture. Capture loss cancels an active pointer sequence without clearing keyboard focus, held keys, or already completed actions/gestures; ordinary Win32 release-capture therefore cannot erase a completed click or drag. Focus loss cancels the whole interaction. Queued window gestures retain the committed reference geometry and the latest update until a declaration can consume it.

Testbed now uses this adapter exclusively for its movable/resizable/collapsible information window and interactive skin gallery. Its scene input registers behind UI priority, uses authoritative UI capture queries, and cancels held state on native focus loss. Clipboard/native selection exchange remains OS-owned and borrowed. The borrowed `UiPaintContext.textInput` exposes the Frame-owned service; the visual edit controls remain the next toolkit increment. Joined world/GPU teardown releases adapter subscriptions before native services disappear.

## Text edit sessions

`text_edit_session.h` supplies `UiTextEditSession`, an event-thread adapter that borrows `ITextInputService` and applies copied native events to a scoped `Ui::EditModel`. The service and arena outlive the adapter. `UiTextEditOwner` combines widget identity, declaration generation and model generation; increment the relevant generation when replacing a declaration or its backing model. No pointer to the model is retained between calls.

Begin only after the host gives an editor focus, with its committed text/selection and caret rectangle in native window-client pixels. `drain` applies events once, keeps preedit outside committed text/history, and publishes a new surrounding snapshot after accepted edits. `refresh` updates caret geometry and accepts only the model state produced by the previous drain. Keep the OS service's single active session exclusively owned by this adapter while its token is valid.

Drain before host keyboard/pointer edits. Call `end` with the old owner and model before a local text/selection edit, focus transfer, removal, replacement or root retirement, then begin a new session after editing if focus remains. This invalidates queued events for the old selection and clears transient preedit. An external model mutation detected by `drain` cancels the native token and preserves that host state. A foreign owner/model never receives queued events or composition cleanup. Destruction releases the native token without dereferencing a model, so explicit host end is required when the old model's transient composition also needs cleanup.

Native surrounding deletion must match the exact published revision and model snapshot. Its byte ranges must also be complete graphemes. Nonzero deletion against a selected range is explicitly rejected until the Wayland selection-exclusion transaction is implemented; no queued commit from that batch is applied to the wrong range. Surrounding updates produced by native events are labelled as input-method feedback. A deletion after an unpublished commit, a split-grapheme deletion, malformed event, queue overflow, native cancellation or rejected model edit terminates that session explicitly. Earlier accepted commits remain committed and undoable. Native caret visibility is exposed separately for the future preedit paint adapter.

This foundation does not yet bind sessions automatically to Builder edit-box declarations, route edit keys, paint caret/selection/preedit, or issue clipboard commands. Those operations will use this adapter in the next increment; the independent GPU layer continues to receive immutable paint only.
