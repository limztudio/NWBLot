# Editable UTF8 model

`EditModel` owns committed UTF8 text, byte selections, copied undo/redo records, grapheme boundaries, and transient composition text in the caller's `Core::Alloc::GlobalArena`. The arena must outlive the model and every view borrowed from it. This domain has no native window, OS input, ECS, font, layout, or GPU dependency. `nwb_ui_edit` links the common UI type/allocator domain; callers handle input delivery and rendering.

The model starts empty with a nonzero revision. `setText` supplies an external committed value, places the selection at the end, and resets history and composition. `replaceSelection`, `backspace`, `eraseForward`, and `eraseSurrounding` create one undo record for each committed text change. Successful no-op edits do not advance the text revision. Selection and composition changes do not advance it either; callers track those view properties separately. Every invalid UTF8 value, invalid byte position, multiline value, or byte-limit failure preserves committed text, selection, revision, history, and existing composition.

`anchor()` and `caret()` are UTF8 byte offsets. Ordinary selection positions must match `graphemeBoundaries()`, including both ends of the string. Left/right navigation and deletion use whole extended grapheme clusters, so they preserve combining sequences, Korean jamo, emoji modifiers/ZWJ sequences, regional-indicator flags, and Indic conjuncts. Inserting text can merge adjacent clusters; the resulting caret uses the first valid boundary at or after the inserted bytes. Home/end operate on the single line. Shift navigation retains the anchor. Word navigation groups whitespace, ASCII punctuation, and all remaining graphemes; it does not claim Unicode linguistic word segmentation or dictionary-based word movement.

The single-line policy rejects NUL, CR, LF, LINE SEPARATOR, and PARAGRAPH SEPARATOR. Other valid Unicode scalars are preserved byte-for-byte without normalization. Native input and clipboard adapters may apply their own character policy before passing a value to the model.

Default limits allow 4096 committed bytes, 64 copied history records, and 131072 copied history bytes. Constructor limits are capped at 1048576 text bytes, 256 records, and 16777216 history bytes. A history record owns both full before/after text and their selections. The oldest complete records are evicted to meet both bounds; branching after undo discards future records. If a new edit cannot fit even one history record, history is cleared so an older undo cannot silently skip the latest edit. `eraseSurrounding(beforeBytes, afterBytes)` validates native byte distances from the current caret and uses whole grapheme edges. It preserves the actual before-selection in its undo record, without introducing an artificial selection around the deletion. A zero/zero surrounding delete is an accepted no-op that preserves selection and preedit. Setting the record limit to zero disables undo. All history strings, vectors, and retained selection state belong to the supplied arena.

`beginComposition()` captures the current replacement selection once. `updateComposition()` changes separate owned preedit text and native preedit selection offsets; it never changes committed text or committed selection. Native preedit offsets must lie on UTF8 scalar boundaries and may lie inside an extended grapheme, as IMEs can select a combining component. An empty preedit update preserves the replacement baseline, allowing platforms that clear the preedit before sending the commit. `commitComposition()` replaces that captured range once and creates one undo record. `cancelComposition()` discards transient state. Accepted ordinary edits, navigation, and selections also cancel preedit; rejected operations preserve it. Callers cancel the native session when their ownership/focus changes and avoid sending a stale native commit to a new model.

# Unicode data and conformance

`GraphemeSegmentation` implements the default extended grapheme rules from [Unicode 17.0.0 UAX #29 revision 47](https://www.unicode.org/reports/tr29/tr29-47.html), including GB9c Indic conjuncts, GB11 extended-pictographic ZWJ sequences, and GB12/13 regional-indicator pairing. General segmentation accepts controls, including CR/LF, for conformance testing. Single-line validation is an explicit editing policy applied on top of the unchanged Unicode boundaries.

The generated property sources live under `unicode/`, separate from the state machine and edit operations. Hangul LV/LVT properties use the normative syllable formula. The other tables are derived from the pinned [GraphemeBreakProperty](https://www.unicode.org/Public/17.0.0/ucd/auxiliary/GraphemeBreakProperty.txt), [DerivedCoreProperties](https://www.unicode.org/Public/17.0.0/ucd/DerivedCoreProperties.txt), and [emoji-data](https://www.unicode.org/Public/17.0.0/ucd/emoji/emoji-data.txt) files. `unicode/sources.json` records every official source URL and SHA256, and `unicode/LICENSE.txt` preserves the Unicode data license.

`unicode/generate_tables.py` regenerates the three property sources and the two test fixture fragments. It verifies the pinned hashes before writing output; it is an explicit maintenance tool and is never run during a normal engine build. With no arguments it downloads the recorded official URLs. `--source-dir <directory>` reads cached files named `gcb.txt`, `incb.txt`, `emoji.txt`, `conformance.txt`, and `license.txt` for offline regeneration.

`edit_grapheme_tests.cpp` checks every one of the 766 official [Unicode 17 GraphemeBreakTest](https://www.unicode.org/Public/17.0.0/ucd/auxiliary/GraphemeBreakTest.txt) cases against the compiled C++ state machine, including controls and degenerate sequences. Model, history, and composition tests separately cover ownership, selections, deletion, byte bounds, branch history, validation failure, preedit cancellation, and preedit-clear-before-commit ordering.
