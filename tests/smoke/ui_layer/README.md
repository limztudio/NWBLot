# Standalone custom UI smoke

`nwb_ui_layer_smoke` creates an ECS world with only `UiLayerSystem` and one `UiPaintComponent`, loads `engine/ui/skins/default/atlas`, and selects `UiLayerPresentation::Standalone`. It renders through the custom GPU layer and acquired backbuffer. The project has no scene renderer or ImGui system.

The first two submitted snapshots are empty, exercising the cleared transparent layer before geometry appears. The deterministic scene then includes opaque solids, half-alpha overlap, a quarter-intensity linear gray, a tinted white atlas sprite, three named nine-slice regions, a transparent arrow sprite, and nested clipping. Geometry uses normalized logical coordinates so both initial and resized extents are observable with the same interior probes.

The CMake target cooks the engine asset root and this fixture's isolated `assets` root into `Testing/ui_layer_runtime/<configuration>/res`. The fixture root uses the existing `project/` virtual asset namespace; the Testbed cooker and the engine default skin are unchanged. The source files separate startup configuration, callback lifecycle, ECS world ownership, and paint scene construction. Capture orchestration and pixel acceptance remain separate Python files.

After building `nwb_ui_layer_smoke`, run `ctest -C dbg -R nwb_ui_layer_ --output-on-failure` from the configured build directory. All eight tests hold the shared `nwb_display` lock and request GPU validation:

- `nwb_ui_layer_framebuffer_smoke` uses the existing `FramebufferCapture` observer to copy a completed 960x540 acquired backbuffer after 60 presentation frames. It stores `ui_layer.bmp`, the collected launch log, and `pixels.json` under `Testing/smoke/<configuration>/ui_layer_framebuffer`.
- `nwb_ui_layer_resize_smoke` uses the existing desktop capture helper to verify a rendered 960x540 client, resize it to 800x600, confirm the graphics resize marker, and capture the new client. It checks the same pixels before and after resize and stores both BMPs plus `pixels.json` under the corresponding `ui_layer_resize` directory.
- `nwb_ui_layer_interaction_smoke` opts into the separate interactive scene with `NWB_UI_LAYER_INTERACTIVE=1`. It drives native input and captures 14 displayed model states: initial state, first click, Space and Enter repeat suppression, Tab/Shift-Tab focus, checkbox changes, disabled-button blocking, drag/release outside, focus-loss cancellation, and resize followed by first click/reset. Nine exact action logs also confirm that activations are consumed once. It stores stage BMPs, the launch log, and `interaction.json` under `ui_layer_interaction`.

`nwb_ui_layer_window_smoke` selects `NWB_UI_LAYER_WINDOW=1` and isolates a movable/resizable/collapsible custom window with a label, separator, button, and Lock checkbox. Production `windowMetrics()` and `WindowLayout` supply native input coordinates. Separate marker pixels encode the host model and generation; frame/title/body/clear-margin probes verify the corresponding displayed window. Windows checks 20 displayed stages and six exact action logs: first click, complete drag/resize before a callback, minimum size, collapse/body inactivity/expand, locked movement/resize, focus/capture cancellation and recovery, pointer leave during drag, and client resize followed by its first drag/click. X11 provides 17 stages and five action logs, omitting Windows-specific leave/capture-change delivery. The test stores stage BMPs, `window.log`, and `window.json` under `ui_layer_window`.

`nwb_ui_layer_window_skin_smoke` reruns the complete window sequence with `NWB_UI_LAYER_WINDOW_SKIN=1` and loads `project/ui/skins/alternate/atlas` plus its referenced replacement texture. Its amber title and green frame have remapped UV regions, different content padding, and a 36-pixel title instead of the default 40 pixels. Native coordinates come from the selected skin metrics, while independent interior probes require the authored title/body RGB values and the expected title height. These probes are separated from marker pixels, text, controls, and the resize glyph, including at the 180x110 minimum. A fallback to the default texture, default atlas UVs, or default title padding fails this gate. It stores the same stage captures and reports under `ui_layer_window_skin`.

`nwb_ui_layer_edit_smoke` selects `NWB_UI_LAYER_EDIT=1` and isolates two single-line edit boxes with application-owned Unicode models. The first starts with Latin and Korean text; the second is a clipboard destination. Numeric markers in each frozen snapshot encode both documents' UTF8 byte lengths, text hashes, byte selections, focus, read-only mode, visibility, and state sequence. The harness checks matching marker pixels alongside actual edit skin, selection, geometry, and clip-gutter pixels. It exercises Korean grapheme Backspace, native text commits, undo/redo, Shift selection, clipboard copy/cut/paste across owners, read-only copy and editing barriers, external model replacement, interleaved text/arrow/text order, queued text at a focus change, omission of a focused widget, native focus loss, client resize, and horizontal scrolling. F5 toggles the first field's read-only mode, F6 omits it, and F7 replaces both models' text; these fixture-only keys reach the application before the UI layer. It stores stage BMPs, `edit.log`, and `edit.json` under `ui_layer_edit`.

The edit harness uses Win32 `WM_CHAR` commits and native Control/Shift modifiers, or X11 ASCII key events. Its Korean seed checks Unicode editing and font coverage without claiming live IME qualification. A queued posted event batch can straddle frames: a commit may reach its original document before focus changes, but it must never enter the new owner. Deterministic stale-session and clipboard fencing are covered by unit tests. The fixture requires a 390x350 logical client; unsupported desktop input/capture and insufficient display space return skip code 77.

`nwb_ui_layer_popup_smoke` selects `NWB_UI_LAYER_POPUP=1` and owns a separate popup state, two text models, and ordinary underlying controls. Its popup contains two choice buttons, a checkbox, and an edit box. A second host root with a higher order paints an opaque red rectangle behind the popup and a blue sentinel at the viewport edge. Numeric markers encode popup visibility, modal mode, underlying activations, selection, checkbox state, both edit focus states, placement modes, text bytes, and the frozen snapshot sequence. The capture must match both model markers and the popup atlas interior. A modal popup must dim the late-root sentinel and markers through the same overlay composition.

The popup harness checks displayed states for opening above a later root, keyboard checkbox selection, Tab and Shift+Tab wrapping, native editing in popup content, Escape, accepted-close focus restoration, keyboard and pointer choice closing, outside press/release consumption before the next click, modal blocking and dimming, vertical and horizontal placement flips, viewport clamping, resize, omission during a held pointer sequence, and native focus-loss dismissal. F5 moves the anchor to the viewport edge, F6 selects horizontal placement, and F7 omits/restores the popup declaration. The fixture-only keys are separate from production popup behavior. It stores stage BMPs, `popup.log`, and `popup.json` under `ui_layer_popup_default`. Both popup skin sequences pass all 31 displayed-state gates on Windows ARM64 / Clang 22.1.4 `dbg` with GPU validation; all nine UI/Testbed smoke tests pass together.

`nwb_ui_layer_popup_skin_smoke` runs the same sequence with `NWB_UI_LAYER_POPUP_SKIN=1` and the isolated alternate atlas. The alternate skin keeps its authored popup color while remapping its UV tile, so the independent popup interior probe also catches a fixed default UV lookup. The replacement texture is reused; the increment adds no texture assets. It stores results under `ui_layer_popup_alternate`. Both popup tests require at least a 600x390 logical client. Native input uses the existing Win32/X11 helper, and text events bypass live IME composition. The harness does not qualify native Wayland input, physical pointer grabs, or native Linux execution on a Windows host.

Regenerate the three alternate assets with `python tests/smoke/ui_layer/generate_alternate_skin.py --tex-conv <built-tex_conv>`. The default converter path is `__exec/windows/arm64/full/opt/tex_conv.exe`; other platforms can pass their built executable. The script imports the engine artwork generator, overrides its palette in memory, reverses tile placement, and writes CRLF atlas metadata plus the converted UASTC texture. Its temporary PNG and intermediate atlas live under the ignored `__artifacts/custom_ui/alternate_skin` directory. The checked-in fixture contains only `atlas.nwb`, `texture.nwb`, and `texture.tex`; no source PNG is required.

The passive scene's 25 probes check clear margins, draw order, linear alpha blending, one SDR output conversion, sampled skin tint, named atlas colors, sprite transparency, and intersected clips. Solid tolerances are four byte values or less; atlas probes allow compression and filtering differences of up to eight values. Each failure records its expected and observed RGB, location, and tolerance. Shared capture infrastructure rejects warnings, errors, assertions, validation failures, and abnormal shutdown. Unsupported framebuffer readback or unavailable desktop capture is reported as CTest skip code 77.

HDR composition has separate numeric tests in the graphics asset integration suite. This smoke fixes SDR output so framebuffer bytes have deterministic acceptance values on an SDR display.

The interaction harness supports Win32 message delivery and an X11 event/focus path. The earlier interaction increment was run on Windows ARM64 with posted key/button/focus messages and a native Shift modifier; it does not qualify physical pointer grabs, Wayland input, or native Linux execution. An unavailable supported desktop input/capture path returns skip code 77. The ordinary framebuffer and resize tests explicitly select the passive scene. All eight CTest runs set every scene and skin selector explicitly. The window tests require at least a 430x270 logical client so the window and model strip stay separate; insufficient display space also returns skip code 77.
