# Custom UI ECS adapter

`UiLayerSystem` borrows the world, graphics runtime, input dispatcher, clipboard/text-input services and asset manager. It owns `Ui::Context`, `Ui::Builder`, text/paint services and the independent `Ui::GpuRenderer`. `UiPaintContext.ui` exposes the builder alongside low-level paint/text. Components stay in `components.h`; CPU UI code includes no ECS/native headers and GPU work sees only frozen paint. The former ImGui system, draw callbacks, upload/texture helpers and forwarding path have been removed.

Visible `UiPaintComponent` roots are sorted by explicit `order`, then their complete generational EntityID. Removing/hiding a root retires its input/actions even while a GPU snapshot is pending. Callbacks execute on the owning main thread only when a new frame can be built. Their mutable captured state stays alive if the callback removes or replaces its component. A pending generation retries frozen data without rebuilding callbacks or replaying their actions.

The candidate hit layout has the same generation as submitted paint. Final output acceptance identifies the acquired backbuffer used by that generation; only its exact native presentation receipt publishes the layout. A later scene-only frame cannot qualify it. Rejected matching presentation abandons the candidate before rebuilding. This is accepted native queueing, rather than display scan-out completion. Resize/DPI/device boundaries clear stale input geometry.

Native handler dispatch joins outstanding world work before reading roots. System update uses scheduler component dependencies and never joins its own task. Coordinates are logical; the OS dispatcher normalizes DPI. The first held pointer button assigns scene/custom ownership through release, including wheel input. Supported held UI keys keep their owner across focus transfer. Focus broadcasts and key/button releases visit all handlers.

Win32, X11 and Wayland deliver native pointer leave and capture-loss boundaries. Leave clears hover while retaining capture. Capture loss cancels an active pointer sequence without clearing keyboard focus, held keys, or already completed actions/gestures; ordinary Win32 release-capture therefore cannot erase a completed click or drag. Focus loss cancels the whole interaction. Queued window gestures retain the committed reference geometry and the latest update until a declaration can consume it.

Testbed now uses this adapter exclusively for its movable/resizable/collapsible information window, interactive skin gallery, popup menu and editable/read-only text fields. Its scene input registers behind UI priority, uses authoritative UI capture queries, and cancels held state on native focus loss. Clipboard/native selection exchange and IME remain OS-owned and borrowed. `UiPaintContext.clipboard` and `textInput` expose Frame-owned services; `UiLayerSystem` installs the visual edit-box host automatically. Joined world/GPU teardown releases adapter subscriptions before native services disappear.

## Popup input and presentation

Popup state and behavior live in the CPU toolkit. ECS callbacks borrow application-owned `Ui::PopupState` through `Builder::beginPopup()`/`endPopup()` after panel/window scopes have ended or inside another user popup. Child state and control/source loans remain borrowed through the outermost popup end. Only a visible `true` begin requires end. The adapter retains no popup-state pointer across callbacks or GPU work. The state exposes prepared placement; `Context` separately retains copied candidate scopes and publishes their geometry only for the exact accepted paint/presentation generation.

A popup scope token includes the widget ID, declaration lifetime, state instance lifetime and open generation. Targets, activations and pointer capture carry that exact token. Closing/replacing/reopening a scope fences its old actions, including later children in the same body, and removal/hidden-root handling retires stale popup interaction immediately. The top accepted popup owns pointer routing and Tab/Shift+Tab traversal. Autofocus chooses its first eligible child on acceptance. Explicit accepted close restores saved focus only when that declaration remains eligible; immediate declaration/root retirement may restore an eligible lower target at retirement. Native focus loss closes popups and cancels saved restoration into the unfocused window. A loss-generation fence also closes delayed candidate scopes, even if native focus returns before their acceptance. Focus gain alone does not reopen or restore a closing scope.

Popup outside/Escape policies decide dismissal. The ECS native handler preserves the custom UI owner through a held key/button sequence and its release, including when the popup closes before release. A dismissing outside click cannot activate a lower control or start scene input. With outside dismissal disabled, that sequence stays consumed while the popup remains open. Capture loss retains the existing pointer cancellation contract; native focus loss closes popup scopes alongside cancelling editing and scene/UI held interaction.

Overlay paint uses positive command layers above ordinary layer-zero roots, regardless of later component order. A modal draws its viewport backdrop before its own popup content. These layers stay inside the existing independent GPU UI target, final scene composition and accepted snapshot lifecycle. The selected skin resolves `popup.normal` with `panel.normal` fallback; ECS has no hardcoded default texture or popup-specific GPU task.

`UiEditBoxHost` keeps the first Escape with active transient preedit. A subsequent editor cancel requests `PopupDismissReason::Escape` from the CPU router; if there is no dismissible accepted popup, the ordinary editor cancellation path clears focus. Entries and candidate/displayed geometry carry their popup token, so reusing the same edit model after reopening cancels old native/key intentions and pending cut/paste mutation before the new loan. This preserves OS composition ownership and prevents popup dismissal from committing or undoing preedit text. The same borrowed Win32/X11/Wayland service interfaces are used inside and outside popup content.

Each nested popup owns an independent Builder scope and restores its parent container on child end. Fixed-height keyed lists participate in popup scopes and accepted geometry. Ordinary and searchable combo fields declared in panels/windows or nested user popups compose their own popup content. Tooltips attach to panel/window or plain-popup content, and context menus attach to panel/window or nested-popup content. Application-specific submenu navigation and live IME qualification remain separate work. Linux target syntax validation with genuine Linux headers checks compile compatibility; it does not establish native Linux linking or X11/Wayland compositor execution. Posted Win32/X11 smoke events also do not qualify physical pointer grabs or live input-method behavior.

The shared input adapter maps Up/Down/PageUp/PageDown and positioned wheel deltas into the toolkit's copied control actions. Win32, X11 and Wayland use the same dispatcher path; X11 wheel events publish their event position before the delta so the list under the wheel is the one hit-tested. Existing scene/UI held-pointer ownership remains in force. Selection, list navigation and scrolling are toolkit behavior; clipboard and IME remain borrowed OS services.

## Tooltip and context-menu integration

ECS callbacks declare an anchor item, then call `ui.tooltip(key, anchorKey, text, state, options)` or `ui.contextMenu(key, anchorKey, source, state, options)` in the same container scope. The application owns `TooltipState`, `ContextMenuState` and the keyed command source. Keep them alive and unchanged through the enclosing `endPanel()`/`endWindow()` or outermost `endPopup()`. Tooltip return values report declaration success; menu results report stable command keys on explicit activation. Apply command side effects after the enclosing scope ends successfully.

The adapter supplies frame delta and held native pointer-button state to Builder. Tooltip delay begins only over accepted enabled geometry in a focused window with a known pointer. Help emits an overlay without a target, Tab stop, popup input scope or native editing session. It preserves existing focus and disappears on leave, pointer activity, disabling, clipping or scope retirement. Closing a plain popup before its end hides its declared tooltips.

Native secondary-button events and Menu/F10 keys enter the shared normalized router. Secondary press, Menu or Shift+F10 requests a context menu using copied accepted anchor geometry and lifetimes. The menu reuses list cursor navigation, stable-key command activation, popup dismissal and saved-focus rules. Disabled commands cannot activate; Escape, outside clicks and native focus loss cancel. Native held-key/button ownership survives menu transitions through release, while source revisions and declaration/state changes fence stale requests and result actions.

Builder retains every ordinary list, combo and menu loan through later deferred callbacks in the enclosing scope, including ended popup children until their outermost end. It validates source snapshots and then performs final model/epoch checks without calling source code before releasing the loans; a later source callback cannot silently change an already painted model. Detected mismatches reject the candidate and preserve explicit application changes. The adapter keeps no application-state/source pointer across callback completion or GPU work. Tooltip/menu paint remains in the same independent UI target, skin atlas and final scene composition; clipboard, selection and IME protocols remain OS-owned.

## Visual edit-box host

`UiEditBoxHost` implements the CPU toolkit's `interface IEditBoxHost`. Source files separate registry/frame/geometry ownership (`edit_box_host.cpp`), native/key/pointer input collection (`edit_box_input.cpp`), temporarily lent model/session operations (`edit_box_model.cpp`), and ordered event/action application (`edit_box_actions.cpp`). `Ui::Builder::editBox` supplies the current widget declaration, application-owned `EditModel` and options; publication supplies a copied `EditBoxView` and placement. The host retains owned text/preedit snapshots, events and grapheme caret stops, never an application-model pointer.

Each owner combines stable widget ID, declaration lifetime and `EditModel::instanceGeneration()`. Copied text, committed/external revisions, selection and composition distinguish local adapter edits from outside changes. `setText()` advances the external revision even when its bytes are unchanged. A changed owner/model snapshot cancels transfers and discards queued old-owner events before borrowing the current model. Hidden or removed declarations retire their entries at frame finish; focus, resize/DPI/device reset and native cancellation invalidate their sessions. Composition cleanup is applied while a matching live model is lent.

Native events are collected before a routed key/selection intent enters the ordered host queue. The next live declaration consumes the matching copied events once in order, including commit/arrow/commit batches. Events remain stamped with their owner and native token. Native surrounding deletion additionally needs the exact published revision and complete grapheme ranges; it cannot silently use a newer selection. Queue overflow clears input/session state instead of delivering a partial sequence to another editor.

The host separates candidate placement from displayed placement. A candidate copies the prepared text/cluster geometry and model/external revision alongside the UI generation. Only `commitFrame()` for the exact accepted paint/presentation generation publishes it. Pointer selection resolves the displayed caret stops and rejects geometry from an earlier model revision or external reset. Native caret rectangles use displayed geometry converted from logical coordinates to window-client pixels. A newer unaccepted candidate cannot move the selection or IME anchor.

Keyboard input adds grapheme/word movement, deletion, select-all, submit/cancel and clipboard/history commands to the existing Tab focus router. Ordinary characters insert text while preserving native input ownership; a valid native text session suppresses duplicate fallback character delivery. Read-only declarations permit navigation/selection/copy and end native composition; disabled declarations leave editing/focus inactive. Preedit is owned separately from committed text, displayed through `EditBoxView`, and committed once to the model/history. Editing keys and Enter stay with active preedit; Escape first cancels it.

`UiEditClipboardController` borrows `IClipboardService`, owns copied request fences and completion text, and never retains a model pointer. Cut deletes only after a successful OS write; paste validates UTF8, normalizes line breaks/tabs to spaces and checks remaining model capacity before one replacement/undo record. Pending mutation is cancelled by a later edit/selection intent, focus/owner change, external replacement, read-only transition or teardown. Unsupported channels and failed writes leave the model intact. `UiClipboardPublications` in `clipboard_publications.*` separately owns bounded immutable Copy requests: the OS has copied the selected UTF8 bytes, so publication can complete after editing, focus transfer, widget removal or ordinary host reset while the service remains alive. Destruction cancels remaining publications. Pointer selection can publish an available native primary-selection channel; middle-button paste requests that channel only for the already focused text target and replaces its current selection. It does not move focus or reposition the caret to the pointer.

Win32 IMM32, X11 XIM and Wayland text-input-v3 behavior remains in `core/os/` and is borrowed through the same capability-aware interface. The widget supports one LTR line with clipped caret/selection/preedit and horizontal scroll. Numeric controls reuse this host through ordered action sinks while owning their typed values in the toolkit edit domain. Live IME composition, native Linux compositor execution, paragraph bidi and multiline editing retain their own qualification or implementation scope.

## Text edit sessions

`text_edit_session.h` supplies `UiTextEditSession`, an event-thread adapter that borrows `ITextInputService` and applies copied native events to a scoped `Ui::EditModel`. The service and arena outlive the adapter. `UiTextEditOwner` combines widget identity, declaration generation and model generation; the visual host uses the retained declaration lifetime and automatic model instance generation. A standalone caller supplies equivalent owner lifetimes. No pointer to the model is retained between calls.

Begin only after the host gives an editor focus, with its committed text/selection and caret rectangle in native window-client pixels. `drain` applies events once, keeps preedit outside committed text/history, and publishes a new surrounding snapshot after accepted edits. `refresh` updates caret geometry and accepts only the model state produced by the previous drain. Keep the OS service's single active session exclusively owned by this adapter while its token is valid.

Drain before host keyboard/pointer edits. Call `end` with the old owner and model before a local text/selection edit, focus transfer, removal, replacement or root retirement, then begin a new session after editing if focus remains. This invalidates queued events for the old selection and clears transient preedit. An external model mutation detected by `drain` cancels the native token and preserves that host state. A foreign owner/model never receives queued events or composition cleanup. Destruction releases the native token without dereferencing a model, so explicit host end is required when the old model's transient composition also needs cleanup.

Native surrounding deletion must match the exact published revision and model snapshot. Its byte ranges must also be complete graphemes. Nonzero deletion against a selected range is explicitly rejected until the Wayland selection-exclusion transaction is implemented; no queued commit from that batch is applied to the wrong range. Surrounding updates produced by native events are labelled as input-method feedback. A deletion after an unpublished commit, a split-grapheme deletion, malformed event, queue overflow, native cancellation or rejected model edit terminates that session explicitly. Earlier accepted commits remain committed and undoable. Native caret visibility is exposed separately and controls visual preedit caret painting.

The visual host uses owned event polling and local-state adoption to place native events and toolkit commands in one ordered stream. Standalone session callers can continue using the direct begin/drain/refresh/end API. Both paths keep model borrowing on the owning thread; the independent GPU layer receives immutable paint only.

Deferred composite editors call `IEditBoxHost::editInPopup()` with the copied popup token before the popup's candidate geometry is emitted. `UiEditBoxHost` uses that identity for native session, clipboard and queued-intention ownership; `publish()` still occurs inside the actual popup scope. The adapter retains owned snapshots and tokens, and lends the model only during the edit call. Normal edit boxes continue to use their active context scope.

Nested query/edit geometry retains the exact child popup token even when declaration and deferred publication occur under different temporary activations. A child's accepted focus transfer cancels the covered native session; restored parent editing starts only after accepted parent geometry and a new declaration. Reopening an ancestor fences delayed child native commits and clipboard completions. Preedit Escape cancels composition first, then a second Escape dismisses only the focused child. Queued service-contract tests cover these transitions without claiming a live native input-method run.

## Ordered edit actions

`UiEditBoxHost::editActions()` implements the toolkit's optional borrowed `IEditActionSink` contract. Submit and Cancel run immediately after their noncomposing command, before later native/text events and before paint snapshot preparation. Copied Blur boundaries preserve preceding text on ordinary focus transfer for action-capable controls while native and clipboard ownership retire immediately. Focus generations permit later same-widget reacquisition without reviving old native sessions or cancelled epochs.

New/rebound/reset or omitted ownership and disabled/read-only transitions invoke Abandon only while a matching model is lent. The host retains copied capability, policy and lifetime fields, never a model or sink pointer. A same-owner external model replacement discards queued old input and preserves the new draft. Sink failure or attempted reentrant host mutation rejects the drain before later callbacks and before borrowed entry storage can be cleared. Existing `edit()` and `editInPopup()` controls retain their ordinary editing policy.
