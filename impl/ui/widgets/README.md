# UI widgets

`Ui::Builder` declares panels and windows, scoped row/column containers, labels, buttons, checkboxes, separators, edit boxes, selectable rows, virtualized lists and ordinary/searchable combos. Tooltips and context menus attach to preceding content items. It shapes text and arranges the content before emitting paint and hit targets in the same order. Application values remain in the host model; the GPU snapshot owns copied geometry and image references.

## Windows

Keep a `WindowState` in the host component or application model. Its bounds, initialized flag, collapsed flag, and pointer gesture baselines persist across callbacks. The builder borrows this object only until the matching `endWindow()`; the object must remain alive throughout that scope. Frozen draw snapshots do not borrow it.

`beginWindow(stableKey, title, state, options)` returns whether content is visible. A collapsed window still opens its window scope. Always call `endWindow()` after a window opens, including when `beginWindow()` returns false for collapse. `Context::failed()` distinguishes an admission failure from collapse. Containers and content controls belong inside the visible-content branch. Panels and windows cannot nest; nested row and column containers provide content composition instead.

`WindowOptions::initialBounds` applies once while `state.initialized` is false. `contentWidthFirstUse` and `contentHeightFirstUse` independently fit the initial content while respecting host and skin minimum sizes. Later callbacks preserve host geometry, including user resize. Bounds and all skin metrics use logical units. The window stays inside the available viewport when it fits; larger minimum sizes remain clipped to the viewport.

The title supplies pointer dragging. The bottom-right corner supplies resizing with minimum bounds. The collapse button participates in Tab/Shift-Tab focus and Enter/Space activation. Turning off a capability discards its pending interaction. Turning off collapse restores visible content. Keys starting with `@window.` are reserved for the window chrome.

Chrome targets capture the complete committed window bounds as their pointer gesture reference. Each press uses the geometry that received the native event, even when the host model already describes a GPU-pending candidate. Active updates retain that press reference; a completed press survives until the next callback. Numeric admission and behavior updates validate candidates before publishing changes.

`windowMetrics()` is available during an open window scope, including a collapsed window. `WindowLayout::Visible`, `Content`, `Collapse`, and `Resize` compute matching logical geometry from those metrics and the host state.

## Skin parts and separators

The semantic skin names are `window.normal`, `window.title`, `window.collapse`, and `separator`. A skin can provide `window.resize`; the default atlas uses its `white` sprite to draw the corner grip. Collapse hover and focus reuse the button states and optional `focus.overlay`. Window padding, title padding, minimum sizes, and the atlas reference density determine the control metrics.

A separator does not receive focus or activation. Its direction selects a horizontal or vertical divider, its length follows a layout size policy, and its thickness is expressed in logical units. Zero thickness selects the atlas minimum for that axis, with a one-unit fallback. A horizontal separator stretches across a column by default; a vertical separator stretches through the row height.

## Source ownership

`BuilderScopeFrame` owns transient layout, declarations, borrowed control loans and the active window/popup state. `Builder` retains shared text, paint, skin, styles and edit services. Ended popup child frames retain their layout and control loans at stable arena-owned addresses until the outermost popup ends.

- `window_behavior.cpp` owns initialization, dragging, resizing, viewport constraints, and candidate validation.
- `window_layout.cpp` owns skin-derived metrics and chrome/content geometry.
- `builder_window.cpp` owns window declaration and balanced content arrangement.
- `window_paint.cpp` owns chrome painting and matching hit targets.
- `builder_separator.cpp` owns divider declaration; `controls_paint.cpp` paints arranged content.

## Keyed lists and scrolling

`Builder::selectable(key, text, selected, options)` paints a selected row and returns one accepted activation. The host owns its selected value. `Builder::virtualList(key, source, state, options)` instead composes a focusable list, fixed-height visible rows and a vertical scrollbar. Keep the `ListState` and `interface IListDataSource` alive through the matching `endPanel()`, `endWindow()` or `endPopup()`. Change the source or explicitly call `state.select()`/`scrollTo()` after that scope ends. Frozen snapshots and accepted input targets retain copied geometry and lifetime values, never these borrowed objects.

The source supplies nonzero unique keys, a unique nonzero instance generation, and a nonzero revision advanced whenever order, count, text or enabled state changes. Generations and revisions must not be reused for a different dataset state. `indexOf()` resolves a key and `findEnabled()` searches inclusively in one direction without wrapping. Implement these efficiently; the toolkit does not scan the full dataset. Row text may use a temporary buffer valid until the next source call. The list immediately shapes and copies it before borrowing another row.

Selection and keyboard cursor are stable keys. Reordering preserves valid enabled keys and ensures the cursor's new index is visible; removal or disabling clears the affected key. Replacing an established source instance clears selection, cursor and offset. `ListResult::selectionChanged` reports selected-key changes, while `activated` reports a row pointer release or first Enter/Space press. Up/Down skip disabled rows; Home/End select an enabled endpoint; PageUp/PageDown use the displayed viewport's row count. `selectOnNavigate=false` moves the cursor without committing selection, as used by combo previews and context-menu commands. An empty list or a list without an enabled cursor consumes Submit as a no-op.

Wheel scrolling preserves selection and uses the accepted step/range. Scrollbar dragging uses its accepted track, thumb and maximum as the press baseline. Multiple pending gestures and control actions are consumed in sequence; coalesced movement carries the sequence of its latest update. A source revision or explicit state change fences old intentions and cancels old capture. Held keys retain release ownership, and a lost control owner cannot revive after a later token reuse. A previously focused list restores focus only when the replacement frame is accepted, with native focus-loss and popup guards.

`ScrollState` stores double offsets; `ScrollLayout` computes logical padded viewport, clipping, proportional/minimum thumb, visible `[firstRow, endRow)` and row bounds. Ancestor clipping culls rows without altering the logical scroll range. The list retains one widget state and emits only visible part targets; visible-row shaping and painting are proportional to that interval. More than 1,024 visible rows rejects a frame, and the existing 4,096-target limit still bounds the complete context. This bound is independent of dataset size. Variable-height rows, horizontal scrolling, multi-selection and generic scroll containers remain future controls.

`Builder::listStyle()` resolves `list.background`, `list.row.normal/hover/selected/disabled`, `scroll.track`, `scroll.thumb` and optional `focus.overlay` from the selected skin. The default and alternate atlases reuse existing texture tiles for new semantic regions. Missing regions use explicitly named panel/button fallbacks within that skin. `SelectablePainter` is shared by standalone rows and list rows. Geometry/state, keyed model behavior, declaration/input, row painting and shared selectable painting live in separate source files.

## Combo boxes

`Builder::comboBox(key, source, state, options)` composes a skinned field, arrow, anchored popup and fixed-height virtualized list. Declare it inside a panel, window or user popup; its internal popup is arranged and painted automatically during the enclosing end. No separate popup callback is required. Keep the application-owned `ComboState` and `interface IListDataSource` alive and unchanged through the matching panel/window or outermost popup end. The source query contract is stable for the complete loan: advance its revision for any dataset change and do not mutate another borrowed dataset from a query callback. Detected epoch/source mismatches reject the candidate frame while preserving explicit application changes. A state instance may own only one combo per frame, including across panels and roots.

`ComboState::selectedKey()` is the committed key. `listState().cursorKey()` is the popup preview. Pointer activation or the first Enter/Space opens the field; Up/Down opens and moves the preview toward an enabled row. Within the popup, Arrow/Page/Home/End navigation skips disabled rows and ensures the cursor is visible without changing the committed key. Enter/Space or a row release commits that enabled key and closes. Escape, outside dismissal and native focus loss cancel preview. Outside dismissal consumes the complete pointer sequence. Empty datasets show the configured placeholder and cannot commit. Tab/Shift-Tab follows the existing popup focus trap. Searchable input adds the query-editor behavior documented below; Tab dismissal/advance remains a later policy.

`ComboResult` reports validity, committed-key changes, explicit commit, opening/closing and current accepted focus during declaration. Accepted popup intentions are consumed before the selected field label is shaped, so a row activation returns `committed` immediately in that callback. The popup then uses the arranged field bounds from the candidate being painted. `bounds()`, `placement()` and `listState().placement()` expose prepared geometry; input remains tied to the separately accepted frame. A fully clipped field suppresses and cancels its popup during scope-end painting.

Explicit `state.select()`, `open()` and `close()` renew the field input lifetime even for unchanged values. Each opening/cancellation renews preview input lifetime. Reordering preserves valid committed and preview keys; removing/disabling a key clears it. A new source instance clears selection/scroll and closes. Recreated or reparented declarations close the old popup while preserving the committed key. Accepted field/popup/list tokens fence old queued clicks, wheel, navigation, thumb drags and held keys. Focus returns only when an eligible field and its matching closed frame are accepted; native focus loss prevents restoration.

`comboStyle()` resolves `combo.normal`, `combo.hover`, `combo.open`, `combo.focused`, `combo.disabled` and `combo.arrow`. The default and replacement skins define the field states as semantic aliases of existing artwork, and popup/rows/scrollbar use their existing skin contracts. Field padding/minimum sizes use the maximum of all states. `combo_state.cpp`, `combo_behavior.cpp`, `builder_combo.cpp`, `combo_input.cpp` and `combo_paint.cpp` separate lifetime, keyed behavior, declaration, input and painting. Popup rows share the existing list painter and scrollbar geometry; dataset size does not determine allocations. Combos and searchable combos also declare inside nested user popups; each automatic popup binds to its exact parent opening. Variable-height rows remain separate work.

## Searchable combos

`Builder::searchComboBox(key, source, state, options)` composes the same skinned combo field and popup with an OS-backed query edit box above the virtualized results. Keep a `SearchComboState` constructed with the owning `GlobalArena`; `state.combo()` exposes its committed key and open state, `state.query()` exposes the independent `EditModel`, and `editorState()` exposes prepared query geometry. `SearchComboOptions::combo` controls the field and list; `queryHeight` and `queryGap` control the popup editor layout.

Implement `interface ISearchableListDataSource` for the full dataset and a cached `filtered()` view. `filter(query)` receives committed UTF8 bytes, copies any bytes it retains, and updates that view only when the query or dataset changes. Query changes must preserve the full source's instance generation, revision and count. The view has its own stable nonzero generation and revision, uses the original unique keys, and provides efficient `indexOf()`/`findEnabled()` lookups. The UI performs no dataset scan or per-result allocation. An application may use an index, arithmetic ranges, or an owned matching-key cache to implement its search policy.

The committed selection is reconciled against the full source, so a query that hides it leaves the field value intact. Query, source and filtered-view changes retire previous result input, reset preview and scroll, then reconcile against the new view. Same-text application query assignments also retire preview input. Reopening retains the query. Empty results remain open and cannot commit a value; disabled results are skipped. Explicit application mutations must wait until the enclosing `endPanel()`, `endWindow()` or outermost `endPopup()` releases all state, query and source loans. Distinct active search controls need independent cached views when their queries differ.

Typing, selection, undo/redo, Home/End and clipboard use the shared edit box. Up/Down/PageUp/PageDown navigate the results while the query keeps focus; Enter commits its preview, and Space remains text input. Tab moves to the results, where Home/End and Space also use normal list behavior. Only committed query bytes filter the view. Result navigation delegated from the query editor is suspended while composing, and editor-origin Enter requires a noncomposing submission. Escape first cancels preedit; a subsequent Escape closes the popup without committing. Outside-click and native focus loss preserve the committed value. All query and result input refers to the last accepted geometry and copied popup/control lifetimes.

`builder_search_combo.cpp` owns editor declaration and popup query geometry. `search_combo.cpp` owns the query/view cache and transactional loan checks. Ordinary and searchable combos share field painting, popup placement, list rows, scrollbars and final GPU composition. Their appearances use the existing `combo.*`, `edit.*`, `popup.*` and `list.*` skin regions, so default and replacement texture/atlas skins use the same control behavior.

## Tooltip and context-menu attachments

Declare `Builder::tooltip(key, anchorKey, text, state, options)` or `Builder::contextMenu(key, anchorKey, source, state, options)` after its anchor item, while still in that item's container scope. `anchorKey` names a preceding item in the same container; it cannot address an item in an outer container, a future item or a separator. The attachment has its own stable key and retained declaration lifetime. Keep each application-owned state instance alive through the enclosing end; one state may own only one attachment per frame, including across panels and roots.

`tooltip()` returns declaration success, including while the help is hidden. `TooltipState::visible()` and `placement()` expose prepared visibility and geometry. Hover must refer to an enabled anchor in the accepted input layout with a known pointer and focused native window. A new eligible hover starts at zero; contiguous updates supplied by `Builder::setDeltaSeconds()` reach `TooltipOptions::delaySeconds`, while zero delay appears immediately. Leaving, disabling, holding a pointer button/capture, native focus loss, changing options or recreating the attachment restarts the delay. Candidate clipping or a higher popup also suppresses help.

A tooltip emits skin/text paint above its owning content without a hit target, popup input scope, Tab stop or focus transfer. `maximumWidth` caps the panel width and clips excess text; `gap` and `side` use the shared anchored placement rules. `tooltipStyle()` resolves `tooltip.normal` with `panel.normal` fallback. Tooltips also work in a plain user popup: closing that popup before `endPopup()` hides its help and emits no orphan overlay. Explicit `TooltipState::reset()` always advances its revision and clears prepared visibility.

`contextMenu()` declares a deferred popup and fixed-height virtualized command list for an anchor in a panel/window or nested user popup. Secondary-button press opens at the accepted pointer position; Menu or Shift+F10 opens at the focused anchor's accepted lower edge. These triggers consume their input without primary activation of the anchor. A secondary press preserves the existing keyboard focus; accepted menu removal restores that eligible prior focus. Its automatic popup reserves its declaration-order layer beneath later user children. Application-specific submenu navigation remains a separate policy.

Provide an `interface IListDataSource` with the same nonzero unique stable keys, instance/revision rules and efficient lookups as a virtual list. `ContextMenuState::cursorKey()` is the preview command. Opening selects the first enabled cursor; Arrow/Page/Home/End navigation skips disabled commands and keeps it visible without dispatching one. Enter/Space or an enabled row release reports `ContextMenuResult::activated` and its nonzero `key`, then closes. Disabled-row clicks and an empty list cannot dispatch a command. Escape, outside dismissal and native focus loss cancel the preview; outside dismissal consumes the complete pointer sequence. The result also reports declaration validity and opening/closing during declaration. Handle the returned application command after the enclosing scope ends successfully.

`ContextMenuOptions` controls size, row height, wheel step and enabled state. Disabling the attachment or anchor closes its menu and removes the trigger. A source revision retires old result intentions and resets cursor/scroll before reseeding enabled preview; an eligible previously focused menu regains its row host only when the matching layout is accepted. Native focus loss prevents that restoration even when focus returns before acceptance. Replacing an established source instance closes the old menu. Recreated/reparented attachment or anchor declarations retire the old popup. Explicit `state.open(anchor)` validates a finite nonnegative rectangle and renews the popup/input lifetime; `close()` advances its revision even when already closed. `placement()` and `listState().placement()` expose prepared popup/list geometry. Menu paint shares the existing `popup.*`, `list.*` and scrollbar skin contracts.

## Enclosing-scope loans

Ordinary lists, combo fields/results and context menus all retain their state and source loans through every later deferred source callback in the same enclosing `endPanel()`, `endWindow()` or outermost `endPopup()` family. Painting an earlier control does not release its loan. Search queries and tooltip state remain borrowed through that end as well. Apply explicit application edits, source revisions or command side effects after that enclosing scope ends; source callbacks must not mutate another borrowed state, query or dataset.

Before releasing any loans, Builder validates all source snapshots and then checks every model/input epoch without calling source code. A later callback that changes an already painted list, combo or menu therefore rejects the candidate frame while preserving the application mutation. Reentrant Builder reset, declaration, scope ending or configuration mutation during a source/edit-host callback also rejects the candidate before clearing borrowed storage. Frozen draw data and accepted targets retain owned paint plus copied keys, tokens and geometry, so they borrow no application state or source across GPU work.

## Nested popup declarations

A visible `beginPopup()` can open within another user popup, including its current row/column. Child end restores the exact parent container, and controls declared afterward retain their original parent identity and layout. A closed child begin returns false and opens no scope. Keep all popup state, list/source, editor, query and annotation loans alive through the outermost popup end; apply command side effects after that end succeeds.

Builder draws surviving popup families only at the outermost end. Closing or reopening an ancestor during the body suppresses its old descendants before deferred callbacks. A model/source mutation during drawing rejects the candidate and stops later stale subtree work. The eight-scope frame bound counts plain user popups and open combo/search/menu children together. Exact parent-opening bindings retire stale child openings on the next declaration; explicitly advancing a child opening lets it bind to a new parent. Layers are reserved in declaration order, so an earlier automatic menu/combo remains below a later user child even though painting is deferred.


## Multiline text area

`Builder::textArea(key, model, state, options)` requires an immutable Multiline `EditModel` and an immovable `TextAreaState`. The default viewport height is 160 logical pixels and uses the ordinary edit skin. Models and viewport state remain lent through the enclosing scope or outermost popup end. Mutating a lent model or invoking `scrollTo()`/`reset()` invalidates that candidate, even if the values return to their previous positions. The same live model or state cannot serve two text-area declarations in one family.

The state exposes the latest prepared placement, two-axis scroll, focus and const navigation snapshots; input continues using the host's accepted geometry until frame publication. `scrollTo(Point)` accepts finite nonnegative offsets atomically and advances its public epoch on every accepted intent. Explicit scrolling survives first binding, idle frames and resize, subject to content clamping. A later observed text, selection, composition or focus intent reveals the caret; rebinding a previously bound state resets the viewport. Internal placement/clamping does not advance the public epoch. `reset()` followed by `scrollTo()` seeds a new initial viewport.

The stack `TextAreaNavigationResolver` freshly shapes the event-position model for each Up/Down/Page action. Up/Down preserves a preferred horizontal column; Page uses the height copied from accepted geometry at key admission and keeps the active caret when no other line is reachable. Preedit suppresses document navigation in the host. Enter and Shift+Enter insert LF, Ctrl+Enter submits, Home/End use hard-line edges and Ctrl+Home/End use document edges. Clipboard/native insertion maps CRLF to LF through the existing OS bridge. Submit/Cancel/Blur/Abandon report actions without restoring application text.

TextAreaState, declaration, resolver, paint and loan validation have separate owners/sources. Layout remains hard-line LTR; soft wrapping and paragraph bidi are later capabilities. Wheel input and draggable scrollbars operate on both axes. `wheelLines` defaults to three; positive horizontal wheel input moves right and positive vertical input moves up. `scrollbarStyle()` supplies replaceable atlas names and metrics. Read-only fields retain scrolling; disabled fields publish no active scrollbar parts.

The reusable `ScrollbarLayout` reserves both bars through coupled visibility, clamps offsets and computes thumbs in f64. Text-area input uses complete copied model/state/policy/viewport stamps. Geometry changes retire queued scrolling before application; ordinary offset repaint preserves drag baselines. A scrollbar press focuses its editor without starting text selection. Track release pages by the accepted viewport. Explicit wheel/thumb scrolling suppresses automatic caret reveal until a later accepted text, selection or ownership intent. Edit events and scroll events have separate queues: when edits change the document first, older copied scrolling is retired and caret reveal takes precedence.


## Radio groups

`Builder::radioGroup(key, source, state, options)` renders the complete group of at most 64 choices with stable nonzero unique keys. Keep its `RadioGroupState` and `interface IListDataSource` alive through the enclosing panel/window or outermost popup end. Advance source revision whenever its order, count, text or enabled flags change. Temporary labels are copied immediately before another source call. Independent states may share one const source; a state can be declared only once per context frame.

The group has one Tab stop. Up/Left and Down/Right wrap through enabled choices; Home/End select an enabled endpoint. Navigation reports selected-key changes without activation. Enter/Space and accepted pointer release activate once, including an already selected choice. Page and wheel actions have no effect in this bounded control. Reordering preserves selected keys, removal and established source replacement clear selection, and a disabled selected choice stays checked. Cursor repair alone does not select another choice. Empty and entirely disabled groups are valid barriers.

`RadioGroupOptions::rowHeight` is a minimum of 32 logical pixels. Uniform rows grow to fit their indicator and tallest shaped label; group height includes every row, padding and gaps. Parent clips hide overflow without introducing scrolling or dropping loan validation. Prepared placement is available for diagnostics; input uses the last published copied targets.

`Builder::radioGroupStyle()` selects radio.normal/hover/pressed/checked/disabled/mark and optional focus.overlay. Missing radio imagery uses explicit checkbox fallbacks; absent hover/pressed/disabled frames use the normal frame with independent tints. A checked choice always uses its checked frame and mark, including when disabled. Metrics are stable across states and frozen with each declaration. Public select/reset intents retire copied input even when their values are unchanged; internal navigation preserves its input lifetime while advancing revision. Separate state, behavior, layout, frame, declaration, loan and paint files own these responsibilities.


## Sliders

`Builder::slider(key, state, options)` declares a continuous horizontal `f64` slider. Keep its `SliderState` alive and avoid public setters until the enclosing panel/window or outermost popup ends. The boolean return validates declaration; read `state.value()` and `state.result()` after a successful scope end. Each attempted unique declaration clears its previous result, and only final callback-free loan validation publishes a valid result. A failed scope can have applied input before a later sibling failure; result invalidity does not promise value rollback.

`SliderOptions` defaults to bounds 0..1, stretch width and minimum height 32. `keyStep=0` derives a finite range/100 step; a positive explicit step affects only keyboard input. Up/Right increase, Down/Left decrease, Home/End choose exact endpoints and Page keys use ten saturating steps. Enter and wheel leave values unchanged. Constant ranges and disabled controls remain pointer barriers. Finite out-of-range application values are visually clamped without rewriting the authoritative value until user input.

The track seeks on pointer down. A thumb press retains the exact accepted `f64` baseline and grab offset; a stationary press preserves earlier key changes, and returning after an applied movement restores the original bits. Stable geometry, clipping, bounds, steps, enabled policy and accepted public setter intents retire old capture/actions before input is applied. Offset-only repaint preserves the press. `sliderStyle()` selects slider.track and slider.thumb.normal/hover/pressed/disabled with explicit scrollbar fallbacks, independent tints and optional focus.overlay. Semantic sprite padding does not replace the widget's own padding; atlas minimum and slice dimensions can grow stable metrics.


## Progress bars

`Builder::progress(key, fraction, options)` copies a finite `f64` fraction and its resolved skin style at declaration. Finite values outside 0..1 clamp visually; nonfinite values reject the candidate. The application owns its value, and may change that value or later styles after declaration without changing the earlier item. A progress bar has no state loan, Tab stop, activation, pointer capture or control token. Tooltips and context menus can attach through the same passive annotation target policy as labels.

`ProgressOptions` defaults to stretch width and minimum height 32. `progressStyle()` selects progress.track and progress.fill, with explicit scrollbar fallbacks, independent linear tints and optional content padding. Track padding and region minima can increase the dimensions; only pixel slice borders divide by reference density. A partial fill draws a fraction-sized nine-slice canvas. For an amount narrower than its minimum, the painter reveals a clipped minimum-sized canvas, preserving the authored borders. Zero emits only the track; full progress uses exact content endpoints.
