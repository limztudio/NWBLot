# Editable UTF8 model

`EditModel` owns committed UTF8 text, byte selections, copied undo/redo records, grapheme boundaries, and transient composition text in the caller's `Core::Alloc::GlobalArena`. The arena must outlive the model and every view borrowed from it. This domain has no native window, OS input, ECS, font, layout, or GPU dependency. `nwb_ui_edit` links the common UI type/allocator domain; callers handle input delivery and rendering.

The model starts empty with a nonzero revision and an automatically assigned `instanceGeneration()` that identifies its lifetime. `setText` supplies an external committed value, places the selection at the end, and resets history and composition. Every accepted `setText` advances `externalRevision()`, including an identical-text reset, so a host can fence queued native/clipboard events across explicit replacement. `replaceSelection`, `backspace`, `eraseForward`, and `eraseSurrounding` create one undo record for each committed text change. Successful no-op edits do not advance the text revision. Selection and composition changes do not advance the text revision; callers also track `selectionGeneration()` and `compositionGeneration()`. Accepted selection intents advance their generation even at identical byte positions, so moving away and back cannot revive pending work. Every invalid UTF8 value, invalid byte position, mode-disallowed value, or byte-limit failure preserves committed text, selection, revisions, history, and existing composition.

`anchor()` and `caret()` are UTF8 byte offsets. Ordinary selection positions must match `graphemeBoundaries()`, including both ends of the string. Left/right navigation and deletion use whole extended grapheme clusters, so they preserve combining sequences, Korean jamo, emoji modifiers/ZWJ sequences, regional-indicator flags, and Indic conjuncts. Inserting text can merge adjacent clusters; the resulting caret uses the first valid boundary at or after the inserted bytes. Home/End operate on the current hard line in Multiline mode and the document in SingleLine mode; DocumentHome/DocumentEnd always use the document edges. Shift navigation retains the anchor. Word navigation and double-click selection group whitespace, ASCII punctuation, and all remaining graphemes; they do not claim Unicode linguistic word segmentation or dictionary-based word movement. A hard line break forms its own selectable run.

The ECS edit host applies a portable double-click policy to native ingress timestamps: a released second primary press on the same live editor, popup and text revision selects a word run when it occurs within 500 milliseconds and four logical UI units of the first press. Dragging after that press extends the selection by whole runs. A moved first press, focus/capture loss, intervening edit or Shift-click starts a new sequence. The thresholds are toolkit policy, not native OS double-click preferences. Input events without an ingress timestamp remain ordinary single clicks, which keeps programmatic event sources deterministic.

The single-line policy rejects NUL, CR, LF, LINE SEPARATOR, and PARAGRAPH SEPARATOR. Other valid Unicode scalars are preserved byte-for-byte without normalization. Native input and clipboard adapters may apply their own character policy before passing a value to the model.

Default limits allow 4096 committed bytes, 64 copied history records, and 131072 copied history bytes. Constructor limits are capped at 1048576 text bytes, 256 records, and 16777216 history bytes. A history record owns both full before/after text and their selections. The oldest complete records are evicted to meet both bounds; branching after undo discards future records. If a new edit cannot fit even one history record, history is cleared so an older undo cannot silently skip the latest edit. `eraseSurrounding(beforeBytes, afterBytes)` validates native byte distances from the current caret and uses whole grapheme edges. It preserves the actual before-selection in its undo record, without introducing an artificial selection around the deletion. A zero/zero surrounding delete is an accepted no-op that preserves selection and preedit. Setting the record limit to zero disables undo. All history strings, vectors, and retained selection state belong to the supplied arena.

`beginComposition()` captures the current replacement selection once. `updateComposition()` changes separate owned preedit text and native preedit selection offsets; it never changes committed text or committed selection. Native preedit offsets must lie on UTF8 scalar boundaries and may lie inside an extended grapheme, as IMEs can select a combining component. An empty preedit update preserves the replacement baseline, allowing platforms that clear the preedit before sending the commit. `commitComposition()` replaces that captured range once and creates one undo record. `cancelComposition()` discards transient state. Accepted ordinary edits, navigation, and selections also cancel preedit; rejected operations preserve it. Callers cancel the native session when their ownership/focus changes and avoid sending a stale native commit to a new model.

`eraseAroundSelection(beforeBytes, afterBytes)` implements selection-excluded native deletion. It deletes before the earlier selection endpoint and after the later endpoint, preserving selected bytes and direction. Both outer intervals become one validated candidate and one undo record. Original cuts and both translated selection endpoints must remain grapheme boundaries; a newly joined seam rejects the operation instead of snapping the selection. Zero counts preserve every model epoch, history and preedit value. The OS event explicitly chooses this basis; caret-based surrounding deletion remains available separately.

## Commands and external text

`commands.h/.cpp` translates resolved `InputCommandIntent` snapshots into editing requests and applies model-local commands. The input binding domain owns physical keyboard shortcuts; gamepad and other input adapters can supply the same semantic commands. Arrows and Backspace/Delete use graphemes; Ctrl adds the documented word-run behavior, Shift extends selection, and Home/End move along the one line. Ctrl+A selects all, Ctrl+C/X/V and Ctrl+Insert/Shift+Delete/Shift+Insert request copy/cut/paste, Ctrl+Z/Y and Ctrl+Shift+Z navigate history, Enter reports submit, and Escape reports cancel. Alt combinations remain with the OS, including AltGr. Repeated clipboard/select-all/submit/cancel keys are suppressed. Active preedit keeps editing keys and Enter with the input method; Escape first cancels preedit without reporting widget cancellation. Read-only mode permits selection and copy while blocking text mutation.

`EditCommandResult` carries clipboard intents and text/selection/composition/action flags; it does not call native services. `impl/ecs_ui/edit_clipboard_controller.*` performs asynchronous cut/paste through the borrowed OS interface and verifies copied owner/model snapshots before applying a mutation. Cut is conditional on a successful copy. The visual host sends ordinary copy through `clipboard_publications.*`, which owns immutable selected bytes and can finish after later edits, focus changes or widget removal. `ApplyEditCommand` itself reports cancellation without undoing application edits or restoring an earlier value. An ordered component action sink can apply its own value-restoration policy at that command boundary.

`NormalizeSingleLineText` in `single_line_text.*` is the clipboard insertion policy. CRLF becomes one space; individual line breaks, Unicode NEXT LINE/LINE SEPARATOR/PARAGRAPH SEPARATOR and tabs become spaces. NUL, other ASCII controls, malformed UTF8 and an excessive normalized byte count are rejected before allocation/mutation. Other scalars remain unchanged. This utility is separate from the raw model's strict single-line validation and does not normalize Unicode composition.

Rendering stays in `impl/ecs_ui/toolkit/widgets/edit_box*`: an owned `EditBoxView` maps model bytes, grapheme boundaries, shaped LTR clusters and transient preedit to clipped text, selection and caret geometry. The application lends its model during a live declaration; frozen paint retains owned text/font resources. The edit domain remains independent of OS, ECS, font and GPU implementations. Paragraph bidi and the visual multiline editor remain separate later domains.

## Ordered component actions

`actions.h` defines `interface IEditActionSink` for Submit, Cancel, Blur and Abandon. A host lends the matching `EditModel` and action sink only for one synchronous event drain. The sink runs at the action's exact position before later copied input and before the Builder text snapshot. It must retain neither reference. Returning false rejects the borrowed transaction and stops later callbacks; an incomplete or invalid draft can accept the action without committing a typed value.

`IEditBoxHost::editActions()` accepts an explicit popup token and this borrowed sink. Its default invalid result makes unsupported hosts fail explicitly. Processing the aggregate flags from an ordinary `edit()` result afterward would lose event order: typing `42`, Enter and `7` in one batch must let Submit observe `42` before the draft becomes `427`. Aggregate submitted/cancelled/blurred/abandoned flags remain observations of the completed drain.

Ordinary focus transfer queues a copied Blur boundary after the owner's preceding text events, then immediately retires native sessions and pending clipboard mutation. A later matching loan can process those events before Blur. Copied focus generations distinguish loss and reacquisition of the same widget before the next loan. Cancellation retires its old focus generation without clearing a later reacquired owner. New/rebound, omitted/recreated or reset action ownership and disabled/read-only policy transitions invoke Abandon at the next live loan; no missing model is accessed during retirement. Explicit same-owner external draft replacement fences old input while preserving the application's replacement.

The ECS host rejects reentrant mutation or reset while a model/action transaction is borrowed, preserving entry and event storage until the rejected drain ends. OS composition still owns Enter and the first Escape during preedit. Restoration can renew external text revisions and native sessions without applying surrounding deletion to a retired native baseline. Component-specific parsing and typed values remain separate from this event/action contract.

## Numeric drafts and typed values

`IntegerEditModel` and `FloatEditModel` own a committed `i64`/finite `f64` and a separate 128-byte `EditModel` draft. Intermediate signs, decimal points and unfinished exponents remain editable without changing the application value. `numeric_parse.*` classifies Complete, Incomplete, Invalid and OutOfRange before conversion; it trims ASCII edge whitespace, accepts decimal syntax only, consumes the whole input and leaves output untouched on failure. Integers never pass through floating-point conversion. `global/text_numeric_format.h` formats into caller-owned bounded storage; finite doubles use shortest roundtrip text, including signed zero.

`submit(bounds)` commits a complete representable draft with Reject or Clamp bounds. A successful unclamped Submit preserves the exact accepted bytes, caret and history; an invalid Submit leaves the draft available for correction. `blur(bounds)` commits valid input and canonicalizes it, or restores the committed value after rejection. Cancel and Abandon restore canonical committed text and clear transient draft history/composition; only Cancel reports a user cancellation. Numeric overflow/underflow is rejected before bounds clamping. Bounds must be finite/ordered and use a supported policy; invalid bounds leave all model state unchanged.

`setValue()` is authoritative even outside current widget bounds, rejects nonfinite doubles, canonicalizes the draft and fences prior input even for the same value. `setDraft()` explicitly replaces a bounded draft without changing the typed value. `revision()` tracks model actions and external changes; draft revisions, external revisions, selections and composition epochs independently track borrowed editing. Dirty compares the current draft bytes with the last accepted draft baseline. `lendDraft()` is a synchronous editing loan and must not escape into asynchronous or GPU work.

# Unicode data and conformance

`GraphemeSegmentation` implements the default extended grapheme rules from [Unicode 17.0.0 UAX #29 revision 47](https://www.unicode.org/reports/tr29/tr29-47.html), including GB9c Indic conjuncts, GB11 extended-pictographic ZWJ sequences, and GB12/13 regional-indicator pairing. General segmentation accepts controls, including CR/LF, for conformance testing. Single-line validation is an explicit editing policy applied on top of the unchanged Unicode boundaries.

The generated property sources live under `unicode/`, separate from the state machine and edit operations. Hangul LV/LVT properties use the normative syllable formula. The other tables are derived from the pinned [GraphemeBreakProperty](https://www.unicode.org/Public/17.0.0/ucd/auxiliary/GraphemeBreakProperty.txt), [DerivedCoreProperties](https://www.unicode.org/Public/17.0.0/ucd/DerivedCoreProperties.txt), and [emoji-data](https://www.unicode.org/Public/17.0.0/ucd/emoji/emoji-data.txt) files. `unicode/sources.json` records every official source URL and SHA256, and `unicode/LICENSE.txt` preserves the Unicode data license.

`unicode/generate_tables.py` regenerates the three property sources and the two test fixture fragments. It verifies the pinned hashes before writing output; it is an explicit maintenance tool and is never run during a normal engine build. With no arguments it downloads the recorded official URLs. `--source-dir <directory>` reads cached files named `gcb.txt`, `incb.txt`, `emoji.txt`, `conformance.txt`, and `license.txt` for offline regeneration.

`edit_grapheme_tests.cpp` checks every one of the 766 official [Unicode 17 GraphemeBreakTest](https://www.unicode.org/Public/17.0.0/ucd/auxiliary/GraphemeBreakTest.txt) cases against the compiled C++ state machine, including controls and degenerate sequences. Model, history, and composition tests separately cover ownership, selections, deletion, byte bounds, branch history, validation failure, preedit cancellation, and preedit-clear-before-commit ordering.

`EditModel::compositionGeneration()` advances when transient composition begins, updates or ends. Committed `revision()` remains independent from preedit; deferred UI loans can compare the composition generation to reject stale snapshots, including begin/cancel cycles that return to identical visible text.

## Multiline content and commands

`EditModel` accepts an immutable third constructor argument, `EditTextMode::SingleLine` by default or `Multiline`. `textMode()` exposes that policy. The multiline model stores canonical LF hard lines and preserves empty/trailing lines. It rejects NUL, CR, Unicode alternate line separators, tabs and other ASCII/C1 controls before any mutation; all existing SingleLine admission behavior remains compatible. Validation also applies to history restoration and preedit without rewriting native preedit byte offsets.

`ValidateMultilineText()` checks canonical document bytes. `NormalizeMultilineText()` is the external insertion policy: CRLF, CR, NEXT LINE, LINE SEPARATOR and PARAGRAPH SEPARATOR become LF, and tabs become one space. Invalid UTF8, unsupported controls or excessive output leave the destination unchanged, including when input aliases the output. Normalization remains outside the raw model and can produce one replacement/history record.

`TranslateEditCommand(intent, repeat, mode)` consumes a resolved command and selection/edit flags, with SingleLine as its default text mode. `Accept` submits a single-line editor and inserts LF in a multiline editor; `Submit` always requests submission. `Newline` explicitly inserts LF. An intent with `edit == false` cannot produce editor commands. In Multiline mode Enter and Shift+Enter insert LF, Ctrl+Enter submits, Home/End address the current hard line and Ctrl+Home/End address the document. Newline repeats are accepted; repeated Submit is suppressed. Read-only blocks newline mutation while allowing selection/navigation/copy. Active preedit owns Enter and editing commands; Escape first cancels preedit. Borrowed ECS clipboard and native Commit adapters apply the multiline insertion policy as one replacement/history record. Native preedit is admitted only in canonical form so its byte offsets are never rewritten. This content/command foundation does not supply vertical geometry navigation, visual text-area layout or multiline host publication.
